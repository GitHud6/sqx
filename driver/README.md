# 硬件驱动模块

`driver` 是硬件资源的唯一适配层。它封装串口、定时器、脉冲输出、限位输入、存储介质和传感器等外设，将设备相关实现隔离在稳定的接口之后。

## 职责

- 初始化和释放外设资源，维护每类驱动的初始化状态。
- 提供普通串口输入队列、实时字节入口和可靠输出接口。
- 为 `stepper` 提供定时器时基与 STEP 脉冲输出后端。
- 将限位输入从 ISR 通知转换为上层可消费的状态或回调。
- 提供 SD 卡挂载、传感器读取等底层能力，供专属模块使用。

## 并发与实时边界

- GPIO、定时器和 RMT 的 ISR 接口必须是常数时间操作，并使用可安全访问的数据与函数。
- ISR 只停止、更新或通知；文件操作、日志、阻塞等待和复杂策略留在任务上下文。
- 上层模块不得绕过 driver 直接配置共享外设，也不得建立第二套 STEP 输出后端。
- 驱动层不解释 G-code、不规划速度、不决定任务生命周期。

## 修改步骤

1. 新增外设前先定义公开接口、初始化顺序、失败状态与资源所有者。
2. 修改中断或 DMA 路径时，逐项确认内存访问属性、临界区长度和通知对象生命周期。
3. 变更硬件配置来源时，只从 `machine` 或构建配置读取，不把设备特征散落到调用方。
4. 修改串口、限位、存储或脉冲驱动后，分别回归对应上层模块的错误和恢复路径。

## 验收标准

- 重复初始化或停止不会泄漏资源或留下失效句柄。
- 上层只通过驱动接口访问外设，硬件细节不扩散到协议和规划层。
- ISR 路径无动态分配、阻塞、文件访问和高频格式化输出。
- 外设不可用时返回明确错误，基础安全停机仍可执行。
