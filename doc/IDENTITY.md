# 通用身份命名整改

## 目标

将源码、构建配置、网页、协议输出、默认网络名称、注释和项目文档中的历史产品标识全部
替换为通用名称。最终源码树中不保留历史公司名、型号名、产品缩写或由它们派生的变量、
文件名、命名空间和持久化命名空间。

本次采用下列标准名称：

| 用途 | 标准值 |
| --- | --- |
| 源码根命名空间 | `laserctl` |
| 工程与构建标识 | `laserctl_idf` |
| 机器配置接口 | `machine_profile`、`machine_axis()`、`machine_laser()` |
| 固件标识 | `LaserController-IDF` |
| 板卡描述 | `ESP32-S3 Laser Controller` |
| 机器描述 | `XY Laser Controller` |
| 网页标题 | `Laser Controller` |
| SoftAP 前缀 | `LaserCtl_XXXX` |
| 运行日志标签 | `laserctl` |
| Wi-Fi NVS 命名空间 | `laserctl_wifi` |
| 分区表文件 | `partitions/laserctl_single_app.csv` |

`XXXX` 继续取 AP MAC 地址最后两个字节，仅用于区分附近设备，不代表型号。

## 边界与取舍

- `$STA/...`、`$RADIO/...` 和 `$WIFI/BEGIN` 是协议路径，不携带产品身份，因此保持不变。
- 芯片、ESP-IDF、FreeRTOS、SDMMC、LIS2DH12 等技术名称是依赖或硬件事实，不属于本次
  清理对象。
- 改用新的 Wi-Fi NVS 命名空间后，已保存的 STA SSID 和密码会被有意视为无效，用户需要
  重新配网。这样最终源码不必永久保留旧命名空间的兼容代码。
- 本次是命名和构建结构的机械重构，不得修改机器参数、引脚数值、Timer/RMT、planner、
  profile、stepper 或任何运动时序。
- 工作目录和远程仓库名称不由 Git 提交管理；所有代码提交完成后，工作目录应单独改名为
  `laser-controller-idf`，远程仓库是否改名由仓库所有者决定。

## 阶段一：建立通用身份来源

新增 header-only `identity/product_identity.hpp`，在 `laserctl::identity` 下集中定义固件
描述、网页标题、AP 前缀和日志标签。将 Wi-Fi 持久化命名空间改为 `laserctl_wifi`，并同步
更新对应 README；不保留兼容迁移代码。

本阶段只建立新身份来源和新的持久化域。机器配置文件、全局源码命名空间与构建 target
仍在下一阶段统一处理，以便本提交的目的只聚焦身份配置和配网重置。

验收标准：

1. 工程可编译，身份配置层不引入任务、动态内存、驱动依赖或运动模块依赖。
2. 首次启动后 Wi-Fi 使用新的持久化域；旧凭证不被读取，重新配置后断电重启仍可恢复。
3. `product_identity.hpp` 是新增对外身份字符串的唯一来源，调用者不复制字符串字面量。
4. 运动、SD 作业、实时控制与网络生命周期的控制流没有改动。
5. 阶段验收后提交，建议提交信息：`建立通用身份与配网存储`。

## 阶段二：全局源码与构建重命名

将所有源文件和头文件的根命名空间替换为 `laserctl`；将机器配置文件和 API 改为
`machine_profile`、`machine_axis()`、`machine_laser()`。同步替换全部 include、调用点、
CMake 源文件列表、项目 target、分区表文件名和默认配置引用。

本阶段同时将协议设备信息、AP SSID 生成和回退值、网页标题、日志标签、代码注释和静态
网页源文件改为引用阶段一的通用身份配置。重新生成嵌入式网页 gzip 资源，确保压缩资源
中也没有旧页面文案。

验收标准：

1. 工程编译通过，且不存在旧机器配置文件、旧 API 或旧根命名空间的有效源码引用。
2. 机器配置中的轴参数、激光参数、引脚定义和 CMake 编译单元与重构前一致。
3. `$I`、默认 AP、网页标题和运行日志均使用阶段一的标准身份。
4. `$H`、单轴/双轴 G1、SD 作业、`!`、`~`、`0x18` 与网络基本连接通过回归；运动执行
   的脉冲、位置和安全语义不变。
5. 阶段验收后提交，建议提交信息：`去除源码中的历史产品命名`。

## 阶段三：文档、目录与零残留审计

更新所有模块 README、根 README、网页可见文案与构建说明，使它们只描述通用控制器。
在排除 `.git`、`build`、抓包和第三方 SDK 后，对源文件、配置、脚本和 Markdown 执行
大小写无关的历史标识扫描；扫描结果必须为空。

完成代码提交后，将本地工作目录改为 `laser-controller-idf`。该目录改名不进入 Git 提交，
但必须在新路径上执行一次干净配置和构建，以验证没有依赖旧绝对路径。

验收标准：

1. 历史标识扫描对源码、配置、脚本和 Markdown 的结果为空；编译产物、Git 历史、抓包和
   第三方依赖不纳入扫描范围。
2. 根 README 与模块 README 只使用通用控制器名称，不公开产品或产线硬件身份。
3. 新目录下可重新配置并构建，生成的固件、分区表和网页资源名称均为通用名称。
4. 完成一次启动与基础运动回归，确认目录改名不影响烧录和运行。
5. 阶段验收后提交文档与审计改动，建议提交信息：`完成通用命名清理`。

## 提交顺序

三阶段必须分别提交。阶段二只能建立在阶段一验收并提交之后；阶段三只能建立在阶段二
验收并提交之后。这样每个提交都有单一目的，可独立回退，不会把身份替换与运动行为变更
混入同一次修改。
