# SD 文件与作业模块

`sd` 负责存储文件访问、上传事务和文件作业供料。它将完整的普通 G-code 行交给 `protocol`，自身不解释路径几何或直接控制运动硬件。

## 职责

- 通过有界访问协调保护挂载、目录遍历、文件读取、写入和删除等文件系统操作。
- 提供路径校验、文件枚举、目录管理和文件下载等存储服务。
- 以临时目标写入上传数据，成功后提交替换，失败时中止并清理未完成事务。
- 使用 `FileReader` 向作业服务提供完整逻辑行及字节进度。
- 管理作业的启动、供料、输入结束、排空、完成与读取故障，并向 `service` 报告输入生命周期。

## 并发与一致性边界

- 文件系统访问由本模块串行协调，上传、列举、读写与作业不能绕过该访问边界。
- 作业供料只负责继续提供输入；已提交给 protocol、planner 或 stepper 的运动由下游按生命周期完成或中止。
- 正常文件结束与读取错误必须区分；正常结束触发排空，错误触发对应的作业故障路径。
- 不支持的文件编码或压缩格式不得被当作普通作业输入。

## 修改步骤

1. 扩展文件操作前，先定义路径校验、访问冲突和返回结果，避免调用方自行操作文件系统。
2. 修改上传流程时，保持临时写入、完整写入确认和原子提交的顺序。
3. 调整作业读取时，确保只向 protocol 提交完整行，并保留输入结束与 I/O 错误的区别。
4. 变更存储生命周期时，联测 `service` 的输入状态和 `httpd` 的访问冲突映射。

## 验收标准

- 并发访问不会破坏已存在文件或作业读取器。
- 上传失败不会留下可被当作完整文件使用的部分内容。
- 文件作业结束后，已提交运动按预期排空；读取故障不会被误报为正常完成。
- 存储模块不解析 G-code 语义，也不直接操作 Timer、RMT 或激光输出。
