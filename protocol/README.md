# 协议模块

`protocol` 是所有控制客户端进入控制核心的统一入口。它负责接收字节、组装普通行、分流实时控制、分派系统与 G-code 请求，并通过调用方指定的输出通道返回协议结果。

## 职责

- 为 UART 和网络适配器提供一致的行组装与命令分派语义。
- 在普通行组装前识别实时控制字节，并交由 `service` 的专用控制入口处理。
- 持有解析器状态，调用 `command`、`motion` 与 `service` 完成普通命令门控和执行。
- 生成标准状态、构建信息和命令响应；网络调用方可使用私有输出回调避免污染 UART 回复。
- 在硬复位或系统运动完成后，协调解析器状态与位置可信状态同步。

## 边界

- 不直接访问 Timer、RMT、GPIO 或 SD 文件句柄。
- 不因客户端类型改变安全语义；UART、HTTP、WebSocket 等都必须经过相同的 normal-input gate。
- 实时入口不应被当作普通文本行处理，也不能在硬件 ISR 中执行复杂清理。
- 任务执行、暂停、恢复、复位和故障状态的最终所有权属于 `service`。

## 修改步骤

1. 扩展输入来源时先接入既有行组装、实时分流和响应回调，不复制命令执行逻辑。
2. 修改响应格式时保持普通响应与实时状态的边界清晰。
3. 修改复位或位置同步时，联测 `service`、`command` 和 `stepper` 的位置可信状态。
4. 保持协议任务可阻塞，禁止将解析、锁或格式化工作移入 ISR。

## 验收标准

- 不同客户端执行同一正常输入时得到一致的接受与拒绝结果。
- 实时控制可绕过行组装，普通输入不能绕过任务门控。
- 硬复位后旧输入和旧解析状态不会继续生效。
- 失败响应只写入所属调用方的输出通道。
