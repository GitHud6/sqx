# 任务协调模块

`service` 是任务生命周期与安全策略的唯一协调者。它把多个输入源、运动执行、激光许可、系统运动和故障处置组织为串行状态机，但不承担 G-code 解析、速度规划或脉冲输出。

## 职责

- 维护空闲、启动、运行、暂停、恢复、完成、中止和故障等任务状态。
- 串行处理输入源开始、供料、结束、中止与故障事件，并控制已排队运动的排空策略。
- 为每种客户端提供统一的普通输入门控；实时控制走独立入口。
- 协调硬复位、安全中止、暂停/继续、激光关闭、planner 清理和位置可信状态。
- 向协议层提供可观察的状态与故障原因。

## 并发与安全边界

- 事件由 service 任务串行消费；生产者只投递有界事件，不能直接改写状态机。
- 硬复位和确认的安全故障可在任务上下文立即使输出安全，剩余清理由 service 串行完成。
- 输入结束仅停止后续供料，已接受运动按策略排空；安全中止才会取消未执行工作并使位置失效。
- 不在 GPIO、定时器或通信 ISR 中执行文件访问、队列清理或复杂状态转换。

## 边界

- 不解析普通 G-code，不计算路径速度，不生成 segment。
- 不拥有 SD 文件读取器、网络会话或外设寄存器。
- 不替代 `homing` 的系统运动逻辑，也不替代 `laser` 的底层输出实现。

## 修改步骤

1. 新增事件前先定义它的状态前提、幂等性和失败后的故障原因。
2. 将即时安全动作与异步生命周期清理分开，避免多个任务同时重置下游状态。
3. 变更输入策略时同时检查 UART、网络和 SD 是否仍使用同一普通输入门控。
4. 变更状态或故障枚举后同步更新协议报告与调用方的恢复条件。

## 验收标准

- 非法状态转换被拒绝，合法事件按确定顺序推进状态。
- 暂停保留可恢复的未执行工作；中止和安全故障不会自动恢复。
- 输入结束、执行完成和安全故障能够明确区分。
- 所有客户端遵守同一任务门控与安全策略。
