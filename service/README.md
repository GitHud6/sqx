# service 模块建设计划

`service` 是雕刻任务运行协调模块，负责把协议控制、运动任务、激光输出、SD 作业、归零和安全故障组织成一个统一的生命周期。

该模块参考 `ray2-main` 的 `jobservice` 设计思想，但不直接照搬实现。`service` 只负责任务编排和状态管理，不负责 G-code 解析、速度规划、segment 生成或 STEP/DIR/RMT 脉冲输出。

## 模块边界

### service 负责

- 维护雕刻任务状态和状态转换。
- 接收 `0x18` 硬复位、`!` 暂停、`~` 继续等实时控制意图。
- 协调 planner、stepper、laser、SD 和 homing 的启停及安全联动。
- 处理 SD 卡拔出、读取失败、运动故障等任务级异常。
- 提供统一的任务状态和故障原因供协议层反馈。

### service 不负责

- 不解析普通 G-code。
- 不计算 junction、entry、exit 或 nominal 速度。
- 不生成 profile、segment、AMASS 或 DDA。
- 不进入 Timer/RMT ISR 热路径。
- 不在 GPIO/UART/Timer ISR 中执行阻塞操作、文件操作或复杂状态转换。

底层模块仍保持单一职责：`planner` 管理运动队列，`stepper_prep` 生成 segment，`timer/RMT` 消费 segment，`laser` 控制激光输出，`sd` 负责文件读写，`homing` 负责归零动作。

## 目标状态机

```text
Idle
  -> Starting
  -> Running
  -> HoldRequested
  -> Held
  -> Resuming
  -> Completed
  -> Aborted / Faulted
```

复位和安全故障进入 `Aborted` 或 `Faulted` 后，不得自动恢复运动。位置失效时必须重新归零；普通暂停则保留已执行位置和未执行任务上下文。

状态转换必须由 service 统一串行化。实时入口只提交事件或设置原子请求，不能直接操作 planner 队列、SD 文件或任务句柄。

## 分阶段建设与验收

### 阶段一：接口和状态机骨架

实现 `service` 的公开接口、任务状态、故障原因、事件入口和统一状态查询；暂不改变现有运动行为。

验收成果：

- 工程可以独立编译并启动 service 任务。
- 空闲状态稳定报告为 `Idle`。
- 非法状态转换被拒绝并保留故障原因。
- service 不包含 Timer/RMT、profile 或 segment 生成代码。

### 阶段二：接入 `0x18` 硬复位

将 UART 实时入口识别为 `0x18`，由 service 协调停止激光、停止 Timer/RMT、清空 planner 和 segment、取消 SD/归零，并使机器位置失效。

验收成果：

- 运动中发送 `0x18` 后激光立即关闭，步进输出停止。
- planner 满载、协议任务等待和 SD 作业期间都能清除旧输入。
- 复位后旧 G-code 不会继续执行。
- 状态进入 `Aborted` 或 `Faulted`，必须 `$H` 后才能再次运动。

### 阶段三：接入 `!` 暂停和 `~` 继续

先实现稳定的段边界暂停：当前 segment 完成后停止消费后续 segment，保留 planner 和 prep 上下文；继续时从未执行的 segment 恢复，不重复执行已完成运动。

验收成果：

- 长直线和 SD 雕刻中发送 `!`，运动在有限时间内停止且激光关闭。
- 暂停不会清空 planner，不会使已知位置失效。
- 发送 `~` 后从暂停点继续，位置和步数无跳变、无重复、无丢失。
- 重复发送 `!`、`~` 不会破坏状态机。
- 暂停/继续不改变未触发控制命令时的正常脉冲路径。

后续若需要完全匹配 Grbl 的减速暂停，再单独增加“从当前速度生成减速段”的设计；不得用硬复位冒充暂停，也不得通过重放上一条 G-code 恢复。

### 阶段四：接入统一雕刻任务输入生命周期

将雕刻任务从具体输入介质中抽象出来。UART 串口、Telnet/WebSocket、SD 卡、FFat
等都作为独立输入源接入 `service`，输入源负责提供 G-code，`service` 负责统一协调
任务启动、供料结束、运动排空、完成和中止。

建议输入源向 `service` 报告以下事件：

```text
InputStarted
InputDataAvailable
InputEnded
InputAborted
InputFaulted
```

文件读取和连接管理仍由各自模块负责，`service` 不直接解析 G-code，也不依赖某一种
输入源才能建立安全状态。输入源结束只表示不再有新的运动提交；已经进入 planner 或
segment ring 的运动必须继续执行并自然排空。

SD 正常读到 EOF 和雕刻过程中拔卡，默认都按输入结束处理：停止继续供料、关闭文件，
保留已排队运动，等待运动排空后正常结束任务。SD 拔卡不等同于 `0x18`，不得因此清空
planner、使位置失效或进入运动故障报警。明确的硬复位、运动执行错误、硬限位等仍由
安全控制路径决定是否进入 `Aborted` 或 `Faulted`。

验收成果：

- SD、UART、Telnet/WebSocket 和 FFat 可以复用同一套任务生命周期接口。
- 输入源正常结束后停止继续供料，已提交的 planner/segment 运动完整排空并进入完成状态。
- SD 拔卡后停止文件供料并关闭文件，但不触发 `0x18` 语义、不清空已排队运动、不使位置失效。
- 输入源的连接中断、文件移除和正常 EOF 与运动执行故障能够区分反馈。
- 用户硬复位或明确中止后，输入源句柄、planner 和 segment 均能安全释放。
- 任务完成、暂停、输入结束和故障不会互相误报为普通空闲。

### 阶段五：接入安全联动

接入 homing、limit、加速度计和激光许可状态。不同故障按照安全等级选择暂停、终止或位置失效，所有安全故障禁止自动恢复。

验收成果：

- 归零期间不会被普通雕刻继续命令打断或误恢复。
- 硬限位、加速度异常和 SD 拔卡都能关闭激光并停止相关任务。
- 位置可信状态与实际停止方式一致：可精确保留位置时保持 `Known`，否则进入 `Invalidated`。
- 故障发生后发送 `~` 不会重新启动危险动作。

### 阶段六：状态反馈和回归验证

统一 `$POS/STATUS`、SD 状态和任务故障反馈，补充必要的最小日志；清理重复状态和临时调试输出。

验收成果：

- 状态反馈能区分 `Idle`、`Running`、`Held`、`Completed`、`Aborted` 和 `Faulted`。
- 普通 G-code、SD 雕刻、归零、暂停、继续、硬复位均完成回归测试。
- Timer/RMT ISR 只处理实时脉冲职责，没有新增文件、锁或复杂 service 调用。
- 基准雕刻文件的步数、位置、激光行为和现有基线一致。

## 实施原则

1. 先建立状态机和接口，再逐步接入控制动作；每完成一个阶段并通过验收后再进入下一阶段。
2. 实时字节只负责快速提交控制意图；真正的 planner、SD、laser 和任务清理由 service 任务完成。
3. `0x18` 可以立即触发底层安全停机，但最终状态清理必须经过统一 service 流程。
4. 暂停必须保留可恢复上下文，复位和故障必须明确切断恢复资格。
5. service 不得成为新的“大杂烩模块”；任何脉冲、规划、文件读写和硬件寄存器操作仍归属原模块。
