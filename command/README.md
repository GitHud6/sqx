# G-code 解析模块

`command` 将一行文本形式的 G-code 解析为模态状态更新和一个或多个 `MotionRequest`。它是语法与运动请求之间的事务边界：任何语法、几何或提交错误都不能部分更新解析状态。

## 职责

- 维护单位、距离模式、运动模式、进给、主轴/激光等模态解析状态。
- 识别坐标、进给、功率、圆弧和程序控制相关词，并检查同组冲突与参数范围。
- 将直线或离散后的圆弧表达为 `MotionRequest`，交由 `motion` 批量提交。
- 只有下游完整接受请求后，才提交对应的计划位置和模态状态。

## 边界

- 不访问 GPIO、定时器、RMT、SD 卡或网络连接。
- 不计算 junction、profile、步进周期、AMASS 或 segment。
- 不维护实际机床位置；位置同步由协议和系统运动在位置可信时发起。
- 系统命令和实时控制不在此处解释，分别属于 `protocol` 的分派与实时入口。

## 修改步骤

1. 新增语法或模态前，先扩展解析中间表示和错误枚举。
2. 在提交前完成所有语义、几何和范围检查，保持失败时无状态副作用。
3. 涉及多段路径时使用批量提交，避免只接受部分路径。
4. 同步检查 `motion` 与 `protocol` 是否仍能正确映射错误和位置状态。

## 验收标准

- 非法行不会改变模态状态或计划位置。
- 多段路径要么完整进入 planner，要么完全不进入。
- 正常命令只产生运动请求，不直接产生硬件输出。
- 解析器计划位置与已接受的运动请求保持一致。
