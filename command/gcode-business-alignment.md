# G-code 业务对齐清单

## 文档目标

本文件用于统计 `ray2-idf` 当前 `execute_line()` 与 `RAY2-main` 业务解析行为之间的差异，
并以 LightBurn 灰度雕刻为第一验收目标，规划后续补全顺序。

本文不要求把 `RAY2-main` 的完整 Arduino/Grbl 解析器原样搬入 IDF。RayCube 当前是二维
激光设备，真正需要优先对齐的是：

```text
LightBurn G-code 文件
    -> 完整行读取
    -> G-code 词法与模态解析
    -> XY 目标和激光功率
    -> Planner
    -> RMT STEP/DIR + 激光 PWM
```

## 当前结论

当前 SD 链路已经能打开文件并调用 `execute_line()`。实机状态：

```text
[SD:mounted path=/sd|job=faulted|line=4|fault=command-rejected|error=unsupported-command]
```

这说明当前阻塞点在 G-code 业务兼容性，而不是 SD 挂载或文件逐行读取。
当前 `command/command_executor.cpp` 只实现了以下最小集合：

```text
G0 G1 G20 G21 G90 G91
M3 M4 M5
X Y F S
```

已实现的辅助语义包括：

- 大小写字母统一。
- 空白跳过。
- `;` 行尾注释和括号注释。
- `X0.05S111` 这类词之间没有空格的输入。
- 重复词、模态组冲突、负数、非有限数和基本范围检查。
- G90/G91、G20/G21 的目标坐标计算。
- 每行 `S` 值随 `MotionRequest` 进入 Planner。
- 目标坐标由运动层限制在 RayCube 的 X=`130 mm`、Y=`110 mm` 幅面内。

当前尚未实现的关键能力包括：

- LightBurn 文件头常见的兼容性模态命令。
- 程序结束命令和 SD 作业结束语义。
- 行号、校验和和程序边界标记。
- 坐标系与坐标偏移语义。
- 弧线、暂停、停留等非直线行为。
- 更完整的错误定位，当前只能看到 `unsupported-command`，不能直接看到被拒绝的词。

## 对照基线

### `ray2-idf` 当前实现

主要文件：

- `command/command_executor.hpp`
- `command/command_executor.cpp`
- `motion/motion_submit.cpp`
- `machine/raycube_machine.cpp`
- `sd/sd_job_service.cpp`

当前解析器采用事务模型：先解析到临时结果，运动提交成功后再更新 `ParserState`。这是应当保留的
边界，不应为了增加 G-code 命令而把解析逻辑重新放回 Planner 或 stepper。

### `RAY2-main` 参考实现

主要文件：

- `components/Grbl_Esp32_Source/Grbl_Esp32/src/GCode.h`
- `components/Grbl_Esp32_Source/Grbl_Esp32/src/GCode.cpp`
- `components/Grbl_Esp32_Source/Grbl_Esp32/src/Protocol.cpp`

`RAY2-main` 的 `GCode.h` 明确定义了以下能力类别：

```text
非模态：G4 G10 G28 G28.1 G30 G30.1 G53 G92 G92.1
运动：G0 G1 G2 G3 G38.2 G38.3 G38.4 G38.5 G80
平面：G17 G18 G19
距离：G90 G91
进给模式：G93 G94
单位：G20 G21
刀补：G40（G41/G42 不支持）
刀长：G43.1 G49
坐标系：G54 G55 G56 G57 G58 G59
控制：G61
程序：M0 M1 M2 M30
主轴/激光：M3 M4 M5
冷却：M7 M8 M9
刀具：M6
用户 I/O：M62 M63 M64 M65 M67 M68
覆盖：M56
```

这份列表是移植参考，不代表所有命令都必须进入 RayCube 第一版。

## 缺失功能统计

状态含义：

- `已具备`：当前 IDF 版本已有对应行为。
- `必须补齐`：不补齐无法稳定执行目标 LightBurn 灰度文件，或会造成错误运动/激光行为。
- `兼容接收`：当前 RayCube 不使用该能力，但文件可能发送；只能在确认无副作用后接受。
- `后续实现`：属于完整 Grbl 能力，当前灰度雕刻不是第一优先级。
- `暂不支持`：明确拒绝，不允许静默执行。

| 类别 | 命令/词 | 当前状态 | RayCube 对齐判断 |
| --- | --- | --- | --- |
| 直线运动 | `G0/G1` | 已具备 | 必须保留并继续验证 |
| 单位 | `G20/G21` | 已具备 | 必须保留 |
| 距离模式 | `G90/G91` | 已具备 | 必须保留 |
| XY 轴 | `X/Y` | 已具备 | 必须保留 |
| Z 轴 | `Z` | 明确拒绝 | RayCube 暂不支持，保持拒绝 |
| 进给 | `F` | 已具备 | 必须保留，需确认模态继承 |
| 激光功率 | `S` | 已具备 | 必须和每个运动 block 绑定 |
| 激光模式 | `M3/M4/M5` | 已具备 | 必须保留 |
| XY 平面 | `G17` | 缺失 | 必须兼容接收，设为 XY 平面 |
| 其他平面 | `G18/G19` | 缺失 | 暂不支持，不能生成 XY 运动 |
| 刀补关闭 | `G40` | 缺失 | 必须兼容接收，RayCube 固定关闭刀补 |
| 坐标系选择 | `G54` | 缺失 | 至少必须实现默认 G54 |
| 其他坐标系 | `G55-G59` | 缺失 | 先统计文件是否使用，再决定真实实现或拒绝 |
| 进给模式 | `G94` | 缺失 | 必须兼容接收，当前只支持 mm/min |
| 逆时间进给 | `G93` | 缺失 | 暂不支持，不能当作普通 F 使用 |
| 程序结束 | `M2/M30` | 缺失 | 必须实现作业结束/激光关闭语义 |
| 暂停 | `M0/M1` | 缺失 | 后续实现，至少不能静默当成功完成 |
| 停留 | `G4` | 缺失 | 后续实现；涉及时间语义，不能直接忽略 |
| 冷却 | `M7/M8/M9` | 缺失 | 若 LightBurn 文件出现，可安全兼容为无硬件动作并记录状态 |
| 百分号边界 | `%` | 缺失 | 必须确认是否由文件生成器使用，再实现程序边界 |
| 行号 | `N123` | 缺失 | 建议兼容接收并保存行号，不参与运动 |
| 校验和 | `*123` | 缺失 | 若串口流使用，必须校验；SD 文件可暂不要求 |
| 坐标偏移 | `G92/G92.1` | 缺失 | 后续实现；不能静默忽略 |
| 绝对坐标覆盖 | `G53` | 缺失 | 后续实现；涉及安全坐标语义 |
| 回零/预置点 | `G28/G30` | 缺失 | 暂不支持，不能在未实现时伪造成功 |
| 坐标写入 | `G10` | 缺失 | 暂不支持，依赖持久化坐标系 |
| 弧线 | `G2/G3` | 缺失 | 后续实现；不是当前逐像素灰度主路径 |
| 探测 | `G38.x` | 缺失 | 暂不支持 |
| 取消运动 | `G80` | 缺失 | 后续实现 |
| 刀长 | `G43.1/G49` | 缺失 | RayCube 暂不支持 |
| 刀具 | `M6` | 缺失 | RayCube 暂不支持 |
| 用户 I/O | `M62-M68` | 缺失 | 暂不支持，不能误映射到激光 |
| 覆盖 | `M56` | 缺失 | 暂不支持 |
| 注释 | `;`、`(...)` | 已具备 | 继续保留 |
| 空行 | 空 payload | 已具备 | 必须只产生一次正常跳过 |
| 词法数字 | 小数、正负号、指数 | 部分具备 | 需增加边界测试和错误定位 |

## 第一优先级：LightBurn 灰度最小兼容集

第一优先级不是完整 Grbl，而是让目标灰度文件能够完整走完：

```text
初始化模态
    -> 连续 G1 X/Y S 灰度运动
    -> 行间 F/S 继承
    -> M5 或 M2/M30 关闭激光
    -> Planner 排空
    -> SD 作业 completed
```

建议最小兼容集：

```text
G0 G1 G17 G20 G21 G40 G54 G90 G91 G94
M3 M4 M5 M8 M9 M2 M30
X Y F S
; (...) 空行
```

其中命令分为三种处理策略：

### 必须产生真实业务行为

```text
G0/G1  G20/G21  G90/G91  G94
X/Y/F/S  M3/M4/M5
M2/M30
```

这些命令会改变目标坐标、速度、激光状态或作业生命周期，不能用 no-op 替代。

### 可以安全兼容，但必须维护明确状态

```text
G17 G40 G54 M8 M9
```

当前 RayCube 只使用 XY 平面、固定关闭刀补和默认工作坐标系，因而这些命令可以先实现为
受约束的状态切换。即使底层没有对应硬件，也应在解析结果中明确记录，而不是把未知命令全部吞掉。

### 仍应拒绝

```text
G18 G19 G93 G2 G3 G38.x G10 G28 G30 G53 G92
M0 M1 M6 M62-M68 M56
```

这些命令一旦被静默忽略，可能造成坐标、时间、暂停或硬件行为与发送端理解不一致。

## 当前解析器还需要修正的基础问题

### 1. 必须报告具体拒绝词

当前只返回：

```text
error:unsupported-command
```

这无法定位 LightBurn 文件第 4 行究竟是 `G17`、`G40`、`G54` 还是其他词。后续应在作业状态中至少记录：

```text
line=4|word=G17|error=unsupported-command
```

UART 正常响应仍保持一条 `error`，详细诊断放入 `$SD/STATUS`，避免破坏 LightBurn 的 `ok` 流程。

### 2. 解析边界必须明确

`execute_line()` 使用 `length` 表示 payload 长度，而数字解析基于 `strtod()`。必须明确调用契约为
“payload 已 NUL 结尾”，或者改成严格受 `end` 限制的数字扫描器，避免扫描到 payload 之外的内存。

### 3. 模态命令和运动命令要分别提交

一行可能只包含初始化模态，例如：

```text
G17 G21 G90 G94
```

这类行不应产生空运动 block，但应在语法和模态合法后提交状态。`G1` 没有轴词时则必须按既定策略处理，不能在不同输入来源下行为不同。

### 4. 程序结束必须和 SD 作业排空绑定

收到 `M2/M30` 后不能只返回 `ok`：

1. 停止继续读取后续文件行。
2. 发送安全的激光关闭动作。
3. 等待 Planner、segment 和 RMT 排空。
4. 作业进入 `completed`。

文件自然 EOF 也必须使用同一套安全结束路径。

### 5. 幅面检查必须覆盖模态转换

当前运动层会检查绝对毫米目标是否落在 `[0, 130] x [0, 110]`。补充 `G54/G92/G53` 后，必须先完成
坐标系转换，再进行幅面检查，不能因为新增坐标命令而绕过现有保护。

## 实现步骤与验收标准

### 阶段一：建立真实文件命令清单

实现内容：

1. 为 SD 作业故障记录增加被拒绝的原始 G-code 词或完整行摘要。
2. 对 `longer_studio11.gc`、`cat.gc` 和一份最小 LightBurn 灰度文件做命令统计。
3. 统计 G/M/参数词出现次数、首次出现行号和当前解析结果。
4. 把实际命令集合与本文表格核对，确认第一批不是凭猜测选择。

验收标准：

- 能定位当前第 4 行具体是哪一个 G-code 词导致拒绝。
- 能输出目标文件中所有 G/M 命令的去重清单和首次行号。
- 统计工具或诊断逻辑不改变正常 `ok` 响应数量。
- 明确区分解析器不支持、运动层拒绝和文件读取失败。

结束改动标准：

- 已获得至少一份真实 LightBurn 灰度文件的完整命令清单。

### 阶段二：补齐 LightBurn 初始化兼容命令

实现内容：

1. 增加 `G17`、`G40`、`G54`、`G94` 的解析和状态表示。
2. 增加 `M8/M9` 的受约束兼容语义，不操作不存在的 RayCube 冷却硬件。
3. 保持模态组冲突和重复词检查。
4. 保持 `MotionRequest` 只输出 XY 绝对毫米坐标。

验收标准：

- `G17 G21 G90 G40 G54 G94` 返回一次 `ok`，不产生空运动 block。
- 加入这些初始化命令后，原有 `G1 X0.05 S...` 行行为不变。
- `G18/G19/G93` 仍被明确拒绝。
- 初始化命令失败时，ParserState 不发生部分更新。

结束改动标准：

- 真实文件从文件头进入第一条灰度 `G1`，不再因初始化命令停止。

### 阶段三：补齐程序结束和安全收尾

实现内容：

1. 增加 `M2/M30` 解析结果。
2. 建立 parser 到 SD job 的“程序结束”通知。
3. 统一 `M5`、`M2/M30`、自然 EOF、读取错误和复位的激光关闭路径。
4. 确保 Planner 和 RMT 排空后才报告 `completed`。

验收标准：

- `M2`、`M30` 不产生错误运动。
- 收到程序结束后不再读取后续无关文件行。
- 激光关闭、Planner 排空和作业状态变化顺序可观测。
- 正常文件最终为 `completed`，而不是只返回 `accepted`。
- 错误路径仍为 `faulted`，不被误报为完成。

结束改动标准：

- 一份只包含当前已支持命令的最小 `.gc` 文件能够从 `$SD/RUN` 完整运行并安全结束。

### 阶段四：完善灰度文件高频运动语义

实现内容：

1. 验证 `G1 X0.05S...`、`G1 X0.1S...` 和行间 `F/S` 继承。
2. 验证 G90/G91、G20/G21 与幅面检查的组合。
3. 确认每个有效灰度行最多生成一个运动 block，S 值不串行。
4. 确认 Planner 满载时 SD 行只等待、不丢失、不重复。
5. 验证 508 DPI、6000 mm/min 文件的 UART 实时响应和作业状态查询。

验收标准：

- 输入文件有效行数、MotionRequest 数量和最终 Planner 执行数量可对应。
- 每个运动 block 的 S 值与原始行一致。
- 任务持续运行时 `$SD/STATUS` 可以查询，不触发看门狗。
- 目标坐标始终在 RayCube X/Y 幅面内。
- 连续短行不出现明显串口断供或解析错误。

结束改动标准：

- 目标 LightBurn 灰度 `.gc` 文件可以完成一次实际雕刻，并且图像结果与串口流路径一致。

### 阶段五：按需增加完整 Grbl 能力

实现内容：

按真实产品需求逐项增加：

```text
G92/G92.1、G54-G59、G53
G4
G2/G3
M0/M1
G28/G30
行号与校验和
```

验收标准：

- 每个新增命令都有明确状态变化、运动影响或拒绝语义。
- 新增坐标命令不会绕过幅面检查。
- 弧线由 Planner 可接受的离散运动序列表达，不直接操作 stepper。
- 暂停、复位、取消和恢复路径不会让激光保持开启。

结束改动标准：

- 只有在存在真实文件或产品协议需求时才增加对应能力，不以复制 `RAY2-main` 枚举为完成标准。

## 兼容性验收样例

### 初始化与单段灰度

```gcode
G17 G21 G90 G40 G54 G94
M4 S100
G1 X1 F6000
G1 X1.05 S500
M5
M30
```

预期：初始化行不运动；两条 `G1` 生成正确的 XY 运动；`S` 绑定对应 block；结束后激光关闭，作业排空。

### 增量灰度短行

```gcode
G91
M4 S1000
G1 X0.05 S111 F6000
G1 X0.05 S103.9
G1 X0.05 S98.4
M5
```

预期：三条运动分别增加 `0.05 mm`，后两条继承 `F6000`，功率按各自 S 值执行。

### 必须拒绝的危险或未实现能力

```gcode
G93 F600
G2 X1 Y1 I0 J1
G92 X0
M0
```

在对应功能尚未实现前，预期是明确错误并记录具体词，不得静默返回成功。

## 当前非目标

- 不在本阶段继续优化 gzip 的 32 KiB/8 KiB 内存模型。
- 不把所有 `RAY2-main` G-code 枚举直接复制到 IDF。
- 不为了让文件“跑完”而忽略坐标、暂停、程序结束或激光相关命令。
- 不在解析层直接操作 GPIO、RMT 或 UART。
