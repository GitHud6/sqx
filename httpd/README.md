# HTTP 服务模块

`httpd` 是本地门户与存储访问的 HTTP 适配层。它在网络生命周期允许时启动，负责页面资源、受限命令转发、文件管理与上传接收；所有控制请求仍经 `protocol` 和 `service` 进入统一安全路径。

## 职责

- 启动和停止 HTTP 服务器，维护有限会话预算及连接生命周期日志。
- 提供内嵌页面和静态资源，并按响应类型设置正确的缓存与编码头。
- 将控制文本交给 `network_command_adapter`，不直接调用 motion、planner 或 stepper。
- 将文件列表、读取、删除、目录管理和上传映射到 `sd` 的事务性文件服务。
- 对大文件上传使用有界 DMA 缓冲与独立写入任务，使接收和存储写入能够有限度并行。
- 提供接收链路基准入口，用于隔离网络接收与存储写入性能。

## 并发与资源边界

- ESP-IDF HTTPD 按服务器任务串行执行 handler；每个 handler 必须有界、可失败并尽快返回。
- 会话、URI、请求体、目录响应、上传大小和缓冲数量均受固定预算限制，避免慢客户端耗尽服务资源。
- 上传接收与写入通过有界队列连接；写入失败、队列异常或接收错误必须中止文件事务并释放所有资源。
- HTTP 服务不拥有 WebSocket 会话，二者由 `network_lifecycle` 按网络状态独立启停。
- 链路断开或发送失败属于连接层结果，handler 必须清理自身状态而不能重置控制核心。

## 边界

- 不持有 G-code 解析器、planner 队列、stepper 状态或激光许可。
- 不绕过 `service` 的普通输入门控、暂停、复位和故障语义。
- 不直接操作底层 SD 卡驱动；全部存储事务经 `sd_file_service`。
- 页面资源和 API 行为属于 HTTP 适配层，控制协议细节应维护在独立命令手册中。

## 修改步骤

1. 新增页面资源或接口前，确认请求体、响应体、并发会话和 URI 数量均在明确预算内。
2. 新增控制入口时，复用 `network_command_adapter`，禁止在 handler 内直接执行运动控制。
3. 修改上传管线时，分别检查缓冲获取、接收、入队、写入、完成、提交和失败回收。
4. 调整服务配置、超时或发送策略时，结合连接日志和传输基准验证，不以单次浏览器刷新下结论。
5. 修改文件接口时，复用 `sd` 的结果类型，保持访问冲突和 I/O 故障的 HTTP 映射一致。

## 验收标准

- 网络就绪后，页面、静态资源和存储操作能在有限会话预算下完成。
- 控制请求与 UART、WebSocket 使用一致的协议和安全门控。
- 上传成功后才出现目标文件；任一接收或写入阶段失败均不会提交不完整文件。
- 连接重置、客户端中断和响应发送失败不会遗留上传任务、队列或存储锁。
- HTTP 停止或网络重连不会影响正在运行的本地运动安全状态。
