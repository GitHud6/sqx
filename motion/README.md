# 运动请求模块

`motion` 是 G-code 解析与运动规划之间的提交边界。它将坐标请求校验并量化为不可再解释的几何数据，再交由 `planner` 建立可执行 block。

## 职责

- 校验目标坐标、进给、方向、功率和软限位条件。
- 将连续坐标差量化为每轴整数步数及方向，形成 `MotionGeometry`。
- 将单个或一批 `MotionRequest` 原子提交到 planner。
- 将容量不足、位置不可信或几何非法等结果明确返回给调用方。

## 边界

- 几何量化仅描述步数和方向，不包含周期、速度曲线、segment 或 AMASS。
- 不产生 STEP 脉冲，不更新已执行位置，也不直接操作外设。
- 不自行绕过 planner 队列；所有普通运动必须经 planner 接受。

## 修改步骤

1. 先明确新字段属于请求语义还是量化几何，避免将时序参数放入本层。
2. 在变更量化、软限位或批量提交逻辑后，检查失败时不会留下部分提交。
3. 同步验证 `command` 的计划位置提交条件和 `planner` 的 block 构建条件。

## 验收标准

- 同一请求在相同机器配置下得到稳定的整数步数和方向。
- 超出边界、位置未知或队列不足时不产生新 block。
- 批量请求的接受结果保持全有或全无。
- 本模块不引入 Timer、RMT 或 GPIO 依赖。
