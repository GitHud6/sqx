# G-code 与步进电机最小闭环实施计划

## 目标分析

当前工程已经具备两部分能力：

- `command` 能将 LightBurn 风格的 G-code 行解析为 `MotionRequest`。
- `stepper` 已经在 RayCube 实机上验证了 GPIO 初始化、使能、方向和单脉冲输出。

当前缺口是 `motion_submit()` 仍然只是记录请求并返回 `Accepted`，没有将毫米坐标转换为步数，也没有调用步进驱动。因此下一阶段目标是先打通一条可测量的最小真实运动链路：

```text
G1 X/Y...
  -> execute_line()
  -> MotionRequest
  -> motion_submit()
  -> mm 转换为 steps
  -> 设置 DIR、使能轴
  -> 固定低频输出 STEP
  -> 完成后禁用轴
```

这不是最终 Planner。它只用于证明“解析出的目标位移能够驱动对应轴移动”，并为后续速度、加速度、队列和激光同步建立正确接口。

## 边界与安全约束

`command` 只负责文本解析和事务状态，不直接调用 `stepper`。`motion` 是唯一允许把 `MotionRequest` 转换为运动执行请求的层；`stepper` 只负责 GPIO 时序。

第一版只允许：

- RayCube X/Y 两轴
- `G0/G1` 直线运动
- 低速、单请求同步执行
- 固定频率脉冲
- 不接入连续运动任务、不接入真实 Planner

启动时不自动移动。所有运动必须由明确的 G-code 触发，并且在异常、拒绝和完成路径上恢复电机安全状态。

## 实施步骤与验收标准

### 阶段一：定义最小运动执行参数

实现内容：

1. 在 `motion` 中定义内部执行参数，例如每轴整数步数、方向和脉冲间隔。
2. 从 `machine::raycube_axis()` 读取 `steps_per_mm`、方向反相和最大速度。
3. 明确浮点毫米到整数步数的舍入规则，建议使用四舍五入并拒绝非有限值。
4. 保持 `MotionRequest` 使用绝对毫米坐标，避免运动层再次解释 G90/G91。

阶段验收：

- X/Y 的 `80 steps/mm` 配置被正确使用。
- `0.05 mm` 转换为 4 步，`0.1 mm` 转换为 8 步。
- 目标、起点、进给包含 NaN/Inf 或超出机型限制时返回 `Rejected`。
- `motion` 不修改 `ParserState`，不访问 UART。

### 阶段二：实现单轴单请求执行

实现内容：

1. 校验请求只包含 X 或 Y 的有效位移。
2. 根据 `target_mm - start_mm` 判定方向。
3. 调用 `stepper_init()`，设置方向并使能对应轴。
4. 以固定、保守的脉冲间隔调用 `stepper_pulse()`。
5. 完成后禁用对应轴；任何错误都走禁用清理路径。

阶段验收：

- `G1 X0.1 F600` 能实际移动 X 轴约 0.1 mm。
- `G1 Y0.1 F600` 能实际移动 Y 轴约 0.1 mm。
- 正负方向与目标差值一致。
- 运动过程中另一轴不产生 STEP 脉冲。
- 正常结束和异常结束后，DISABLE 引脚均回到禁用电平。

### 阶段三：接入命令解析闭环

实现内容：

1. 将阶段二执行入口接入 `motion_submit()`。
2. `motion_submit()` 只有在运动真正完成或已可靠入队后才返回 `Accepted`。
3. 运动失败返回 `Rejected`，不要让 `execute_line()` 提交新的 ParserState。
4. 保留 `M4/S` 在 `MotionRequest` 中的值，但本阶段先不驱动真实激光 PWM。

阶段验收：

- 串口发送 `G1 X0.05S111` 时，设备移动约 0.05 mm 并返回一次 `ok`。
- 发送非法命令时不移动，返回一次 `error`。
- 运动失败后，下一条合法命令仍以未提交的位置为起点。
- 每个有效 G-code 行对应一个运动请求，不重复、不丢失。

### 阶段四：加入进给对应的固定频率

实现内容：

1. 使用 `feed_rate_mm_per_min` 和当前直线长度计算总运动时间。
2. 根据总步数计算步间隔，限制在安全的最小和最大频率范围内。
3. 暂时仍采用同步执行，不实现加速度曲线。
4. 对 `G0` 使用单独的保守快速速度上限，但不超过 RayCube 的 `12000 mm/min`。

阶段验收：

- 相同距离下，较大的 F 值运动时间更短。
- F 值不超过机型上限，且不会产生异常高频脉冲。
- X/Y 联动前，单轴速度与预期基本一致。
- 低速和短距离请求不会因为步间隔计算为 0 而失控。

### 阶段五：实现最小 XY 直线插补

实现内容：

1. 计算 X/Y 两轴步数和主轴步数。
2. 使用整数误差累加或 Bresenham 方式安排两轴脉冲比例。
3. 保持两个轴共享同一条运动时间基准。
4. 仍不引入 Planner 前瞻，仅执行一个完整请求。

阶段验收：

- `G1 X1 Y1` 的 X/Y 步数相等，轨迹接近 45 度直线。
- `G1 X1 Y0.5` 的步数比例接近 2:1。
- 运动结束位置误差不超过一个步进单位。
- 两轴的方向、使能和禁用状态均正确。

### 阶段六：为 Planner 和激光同步留出接口

实现内容：

1. 将当前同步执行改为 block 接口，不在 `motion_submit()` 中长期占用命令解析任务。
2. 定义 `Accepted/Busy/Rejected` 的真实含义：接受、队列满、参数或安全条件拒绝。
3. 将每个 block 的 `spindle_power` 保留下来。
4. 预留急停、Feed Hold、Reset 和 Planner 空间检查入口。

阶段验收：

- `motion_submit()` 不再因为执行长距离运动而阻塞 UART 接收路径。
- Planner 满时返回或等待策略明确，不丢弃请求。
- 每个运动 block 的 S 值与对应位移严格绑定。
- 急停或错误时步进输出停止，电机进入安全状态。

## 进入真实 Planner 的停止条件

只有以下条件全部满足后，才开始移植 Planner：

- X/Y 单轴运动已通过实机验证。
- XY 直线插补的步数比例和方向正确。
- `F` 能影响运动速度且有上下限保护。
- `ParserState` 只在运动请求成功后更新。
- 连续 LightBurn 短行不会重复响应、丢请求或错配 S 值。
- 运动执行不再依赖 `protocol` 直接循环调用 `stepper_pulse()`。
- 异常、急停和队列满路径已经定义。

## 暂不实现

本阶段暂不实现：

- 完整 Planner 前瞻和加速度曲线
- G2/G3 弧线
- 回零、限位、软限位完整系统
- 真实激光 PWM 和动态功率曲线
- `$` 设置命令、WiFi、SD、WebUI

这些功能应在最小真实运动闭环稳定后继续拆成独立模块。
